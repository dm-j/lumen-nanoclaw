# 2026-09-18

- Fixed a routing bug where a wake triggered by a message with no `platform_id` left the vault-transcript recipient blank (e.g. "Dispatcher —" instead of "Dispatcher → DMJ"); now falls back to the session's own bound messaging group.
- Added a per-agent-group `wake_script` (`ncl groups config update --wake-script`): runs once at the start of every wake, unconditional on trigger kind — unlike a task's own `--script`, which only fires for scheduled tasks and misses things like an a2a `assign_task` session's opening message. Built to close a gap found while wiring Routine's daily-note awareness (new `daily_note` MCP tools for Routine to read and append to the vault's daily note); confirmed wired and verified end to end (checked against the raw a2a message content, not just Routine's own summary). Two related ideas were captured for later, not yet scoped: folding the daily note into Lumen's own briefing, and letting Routine edit existing note content rather than only append.
- Scoped a roadmap idea for Routine to read/edit the calendar via the vault's local per-event note mirror instead of the ICS-feed fetch. The initial write-up flagged an unknown external sync process touching that mirror as a blocker; later the same day the actual pipeline was identified (a cron job in the personal-vault repo that patches event notes in place and marks removed events cancelled rather than deleting them), which substantially de-risks the concern since a Routine-added local-only event would use its own synthetic id. The plan was also refined to trigger sync from inside the future calendar-read tool itself rather than the group-wide wake script, to avoid taxing every non-calendar wake.
