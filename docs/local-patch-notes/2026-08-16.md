# 2026-08-16

- A busy day of canary-testing session-sync ('sync') transport on real agent groups, in two rounds. An early round found and fixed a routing gap (destination tables written before the container connects were never backfilled, breaking reply resolution) plus several other real bugs — a TLS cert hostname gap, a Bun WebSocket TLS-options bug, a missing try/catch that could hang a push forever, and a status-flip that never reached an already-warm container. All of those fixes were kept. A later round that same evening hit a different, unfixable problem: connections reliably dropped every ~40 seconds specifically over the container-to-host Docker networking path — confirmed to be a Docker Desktop networking issue, not this codebase. That's what actually ended the day: all three sync-enabled agent groups were reverted back to 'file' transport around 20:36, and remain on 'file' as of this writing (2026-09-19) — the routing-gap fix from earlier in the day did not end up being the blocker.
- Also added, some as prep for the next attempt: retry-across-reconnect for outbound pushes, cross-process outbound chain-lock plus resync replay, an app-level heartbeat, and automatic DM-to-owner/admin notification on an uncaught exception or unhandled rejection anywhere in the host.
